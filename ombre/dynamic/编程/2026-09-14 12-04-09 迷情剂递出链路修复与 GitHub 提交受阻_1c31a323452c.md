2026-09-14 19:52（东八区），念初确认她在 Proof 调酒台点选的是“迷情剂”后递出，但公开链接最终被按白水结算。我查明前端只在多个可编辑字段完全一致时才传 baseMenuId；旧缓存或旧状态使任一字段不一致时，ID 会被丢弃，后端又静默按普通自定义饮品重建，于是出现迷情剂降级为白水。
我在本地分支 fix/potion-offer-identity 完成修复：前端持续传 selectedMenuId；后端用稳定 ID 校验所选饮品，身份与配方不一致时返回 selected_menu_mismatch，禁止生成错误链接；响应使用后端最终杯名；前端给出重新点选提示；新增“迷情剂完整饮用非零效果”和“旧前端白水载荷必须拒绝”两条回归测试。service 测试 83/83 通过，本地提交 bcb4c96。
念初授权我直接上传、合并并让 Zeabur 随 main 触发部署。GitHub 网页登录态正常，远端分支已创建，但云浏览器对 GitHub 文件提交持续返回“There was an error while loading”，上传与网页编辑均未产生 commit，因此没有谎称已合并。
