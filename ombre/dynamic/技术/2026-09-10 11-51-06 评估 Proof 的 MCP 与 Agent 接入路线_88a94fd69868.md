东八区时间 2026-09-10，我阅读了 lumingye/Proof 的 README、service 与 Gateway 文档。确认 Proof 本身不是聊天 Agent，而是饮品状态引擎、Agent 独立状态账本、MCP 动作层和可选 Gateway 上下文投递层。我们的 ChatGPT 端可接 MCP，但没有每轮生命周期 hook，因此只能在模型主动调用时读状态，断片为软效果；现有 IO 常驻 Agent 可以增加每轮前置 proof_turn_context 注入，获得自动状态连续性。若要严格硬断片，必须让每轮完整历史经过 Proof Gateway 或建立独立 API Agent，Codex 托管 session 无法删除其已见历史。个人非商用使用符合 PolyForm Noncommercial 许可，但 fork/修改需保留 lumingye 署名与许可证。推荐先部署 Proof service+UI+MCP 到 Zeabur并挂持久卷，再接 ChatGPT MCP与 IO 前置 hook；独立 Gateway Agent作为第二阶段。
